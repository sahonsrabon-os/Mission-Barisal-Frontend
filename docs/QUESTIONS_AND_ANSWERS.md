## Q1. `/home/sahon/Videos/ui/` কি সত্যিই স্বাধীন — `localhost:3000`-এর উপর শতভাগ নির্ভর নয়?

**প্রশ্নের ভিত্তি:** Mission (`localhost:3000`) ভুল রেসপন্স দিতে পারে; তার উপর ভিত্তি করে
গুরুত্বপূর্ণ সিদ্ধান্ত নেওয়া ঠিক নয়।

**তদন্ত (এই সেশনেই):**

1. পুরো প্রজেক্টে `localhost:3000` খোঁজা হলো (কোড+ডক):
   `unnecessary/evidence/P8/Q1_grep_localhost3000.txt` — শুধু **ঐচ্ছিক** `real_provider_test.js`
   (একটি লাইভ প্রোভাইডার-টেস্ট) ও ডকুমেন্টেশনে; প্রোডাক্ট কোডে (server/lib/*.js, index.php)
   **একটিও নেই**।
2. নতুন কোড-পরিবর্তনের পর দুটি নির্ণায়ক স্যুট পুনরায় চালানো — **ফেক LLM (লুপব্যাক) ছাড়া
   কোনো বহিরাগত সার্ভার ছাড়াই**: contract **11/11**, user **11/11**
   (`unnecessary/evidence/P8/Q1_contract_rerun.log`, `Q1_user_rerun.log`)।
3. স্থাপত্য: ইঞ্জিন **OpenAI-সামঞ্জস্য অ্যাডাপ্টার** (যেকোনো base_url) — কোনো নির্দিষ্ট
   প্রোভাইডার-জ্ঞান কোডে নেই; প্রোভাইডার তথ্য শুধু কনফিগ (`.env`/Settings) থেকে আসে।

**উত্তর:** হ্যাঁ — সম্পূর্ণ স্বাধীন। `localhost:3000` শুধু একটি **ঐচ্ছিক** প্রোভাইডার-উদাহরণ।
ইন্ডাস্ট্রি-বেস্ট মডেলই অনুসরণ করা হয়েছে: **নির্ণায়ক টেস্ট নিয়ন্ত্রিত ফেকে** (কনট্রাক্টের
সত্য), **লাইভ টেস্ট আসল প্রোভাইডারে** (রোভিং লেবেল, transient রিট্রাই, সৎ FAIL) — তাই বহিরাগত
ভুল আমাদের সংজ্ঞাকে কখনো দুর্বল করে না।

## Q2. একটি start স্ক্রিপ্ট + `.env` ফাইলে প্রোভাইডার যোগ করা যায়? স্ক্রিপ্ট রান করলে env লোড নেবে? মূল কোডে হাত লাগবে না?

**তদন্ত:**

1. তৈরি: `.env` (chmod 600), `.env.example` (টেমপ্লেট), `start.sh`, `stop.sh`,
   `server/lib/env.js` (লোডার+সিডার), `server/lib/log.js` (লগ)।
2. `OC_DATA=/tmp/... OC_HOME=/tmp/... bash start.sh` — ফল (`unnecessary/evidence/P8/QA_RESULTS.md` Q2.1):
   `env file=/home/sahon/Videos/ui/.env keys=12 applied=12` →
   `provider custom:ollama-remote -> created` + `provider custom:mission-local -> created`
   → `READY pid=... port=8787` → healthz OK।
3. UI-তে (কোনো UI-কনফিগ ছাড়াই) Settings-এ দুটোই **Connected** (Q2.4 স্ক্রিনশট),
   providers JSON-এ কোনো কী নেই (Q2.2)।
4. `index.php` md5 টেস্ট-পরেও একই (Q3.1) — **মূল কোডে শূন্য হাত**; কনফিগ শুধু `.env`-এ।

**প্রাধান্য:** আসল env > `.env` > ডিফল্ট (Q6.1 প্রমাণ: `.env`-এ `127.0.0.1` থাকা সত্ত্বেও
`HOST=0.0.0.0` সেট করে বুটে READY-তে `host=0.0.0.0`)।

**সিডিং-নিয়ম:** এন্ট্রি না থাকলে তৈরি; থাকলে **রাখা হয়** (গ্রাহকের UI-এডিট জয়ী) —
শুধু `OC_PROVIDERS_FORCE=1` দিলে env প্রতি বুটে ফিরিয়ে আনে।

## Q4. LLM ছাড়া (বহিরাগত রেসপন্স না পেলে) কি চলবে? রেসপন্স পেলে UI-র মাধ্যমে এক্সিকিউশন?

- **Q4.2:** মডেল-ড্রপডাউন স্বাভাবিকভাবেই খালি — ইউজার চ্যাট **করতে পারেন না, কিন্তু UI-র

- **এক্সিকিউশন মডেল:** সার্ভার-সাইড টুল-লুপ — LLM tool-call পাঠালেই `read/write/bash`

  টুল-কল→ডিফ)। LLM না থাকলে টুল-লুপ শুরুই হয় না — তাই কোনো অর্থহীন এক্সিকিউশন হয় না।

## Q6. `index.php` কি cPanel-এ চলবে? লোকাল + পাবলিক টানেল URL-এ UI-সার্ভার যোগাযোগ কীভাবে?

**তদন্ত:**

1. `grep '<?php' index.php` → **০ ম্যাচ**। অর্থাৎ এটি কাঁচা JS টেমপ্লেট — PHP দিয়ে
   রান করলে যা হয়: কাঁচা ফাইল (পুরনো হার্ডকোড `path=public_html&project_id=alistiyab_...`
   সহ) + API রুট অস্তিত্বহীন → **ভাঙবে ও লিক হবে**।
2. সঠিক মডেল (যা টেস্ট করা): **Node সার্ভারই `/` রেন্ডার করে সার্ভ করে**
   (A/C/SP/HD/PID ইনজেকশন, পুরনো মান সরানো) — তাই cPanel-এ Node অ্যাপ হিসেবেই চালাতে হবে;
   PHP লাগবে না।
3. **যেকোনো origin:** UI সবসময় same-origin **relative** API পথ ব্যবহার করে
   (`index.live.php?act=ai&...`) — CORS নেই, কুকি (`oc_sid`) + CSRFও same-origin।
   তাই `localhost`, LAN IP, বা পাবলিক টানেল URL — সব একইভাবে কাজ করে।
   - **লাইভ প্রমাণ:** `HOST=0.0.0.0` (আসল env, `.env` জয়ী) বুট করে Chrome থেকে
     `http://192.168.1.145:18921/` খোলা → UI পূর্ণ, providers দেখায়, রাউট-লগে
     non200=0 (`unnecessary/evidence/P8/Q6_lan_origin.png`, Q6.2/Q6.3)।
   - **টানেল:** `cloudflared tunnel --url http://127.0.0.1:8787` (বা `ngrok http 8787`)
     দিলেই পাবলিক URL — টানেল শুধু TCP ফরোয়ার্ড, UI-র কোড-কিছুই বদলায় না।
   - **সতর্কতা:** পাবলিক URL প্রকাশ্য → অবশ্যই `.env`-এ `OC_ACCESS_TOKEN` সেট করুন
     (E6.3: টোকেন ছাড়া shell/API ব্লক)।
